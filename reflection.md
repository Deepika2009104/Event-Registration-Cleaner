# Project Reflection: Event Registration Cleaner

Building the **Event Registration Cleaner** for my AI Capstone Project has been an eye-opening learning experience. Coming into this project as a beginner in Python, I initially assumed that modern Artificial Intelligence tools could solve data cleaning tasks entirely on their own. However, throughout designing and implementing this tool, I discovered that the most effective and dependable real-world systems are not built with AI alone, but rather through a balanced combination of AI, strict programming logic, and thoughtful human oversight.

One of the most important concepts I learned was prompt engineering using structured frameworks. Crafting our `system_prompt.txt` using the five-role framework—Authority, Exemplar, Constraint, Rubric, and Metadata—showed me that guiding an LLM requires precision. By providing clear positive examples and explicit negative constraints, I could command the AI to extract messy data without taking unwanted creative liberties. 

Handling edge cases was one of the biggest challenges I faced. College event registration forms collect surprisingly chaotic inputs: random punctuation, missing phone digits, invalid emails lacking domain dots, and duplicated submissions formatted in completely different styles. At first, my instinct was to ask the AI to "fix" everything. However, during testing, I realized that allowing an LLM to guess missing digits or auto-correct typos like `gnail.com` to `gmail.com` can create serious privacy and operational issues. The AI could easily route event tickets or sensitive notifications to the wrong person.

This is where I truly understood why deterministic Python validation is essential. While the AI is fantastic at understanding messy natural language and extracting relevant fields, Python is necessary for enforcing mathematical and logical boundaries. Python never guesses: it strips symbols, verifies exact 10-digit lengths, checks starting digits, validates email structures, and matches duplicates instantaneously using clean hash lookups. If a record violates these rules, Python flags it without hesitation.

Furthermore, I learned why human judgment remains irreplaceable. When a student enters an invalid email or submits a duplicate ticket, automated software must never delete or arbitrarily change the record. Instead, logging the original entry and the exact failure reason in `problems.csv` allows the human event team to verify student identities directly.

If I were to improve this project in the future, I would like to build a web interface using Streamlit or Flask, add automated SMS verification alerts, and integrate batch API processing to improve speed for tens of thousands of registrations. Overall, this capstone taught me how to write clean, modular Python and gave me the confidence to design responsible, practical AI applications.
